# Phase 9：自动同步

## 目标

把 Phase 7 的“手动上传 / 手动下载”升级成日常基本不用管的自动同步，同时继续保留 revision 冲突保护，避免两台手机互相覆盖。

## 自动同步规则

App 在以下时机会自动检查家庭服务器：

- App 启动后
- App 从后台重新回到前台
- 从“家庭与备份”页面返回
- 用户点击首页右上角同步图标
- 用户在“家庭与备份”点击“立即同步”

同步判断：

1. 本机和服务器 revision 一样，本机有修改：
   - 自动上传。
2. 服务器 revision 比本机新，本机没有修改：
   - 自动下载并恢复服务器最新数据。
3. 服务器 revision 比本机新，本机也有修改：
   - 判定冲突，不自动覆盖任何一边。
4. 网络或服务器不可用：
   - 继续使用本机数据，不影响 App 日常使用。
5. 用户关闭自动同步：
   - 只在手动点击“立即同步”时执行。

## 本机修改跟踪

以下变更会自动标记为“待同步”：

- 新增位置
- 新增物品 / 批量录入
- 更新物品照片 / 位置照片
- 移动物品
- 完成盘库
- 修改库存数量 / 最低库存 / 到期日
- 修改采购清单
- 修改家庭成员
- 手动恢复本机备份

成功上传或下载后，会把本机状态标记为“已同步”，并记录最后成功时间。

## UI

首页右上角增加云同步状态：

- 云朵打勾：已同步
- 云朵关闭：服务器不可连接
- 同步异常图标：存在冲突或 revision 异常
- 转圈：正在同步

“家庭与备份”增加：

- 自动同步开关
- 立即同步按钮
- 本机是否有待同步修改
- 上次同步成功时间

## 服务端变化

新增轻量接口：

`GET /api/v1/families/{family_id}/meta`

仅返回：

- revision
- 是否已有备份
- 更新时间

自动检查时不会每次都下载完整 JSON + 照片备份，只有确定需要下载时才请求完整备份。

## 服务器升级

Phase 9 需要重新部署服务器，因为旧服务器没有 `/meta` 接口：

```bash
cd /opt/family-home-manager
git fetch origin
git checkout feature/phase9-auto-sync
git pull origin feature/phase9-auto-sync

cd server
docker compose down
docker compose up -d --build

curl http://127.0.0.1:8787/health
```

## 真机验收

### A. 自动上传

1. 服务器升级到 Phase 9。
2. 覆盖安装 Phase 9 APK。
3. 打开“家庭与备份”，确认自动同步开启。
4. 点击一次“立即同步”，先让本机和服务器处于同一 revision。
5. 新增一个测试物品。
6. 将 App 切到后台，再重新打开。
7. 首页右上角应短暂显示同步进度，随后显示已同步。
8. “家庭与备份”应显示“本机无待同步修改”，revision 应增加。

### B. 自动下载

需要第二台手机时：

1. 手机 A 新增物品并同步。
2. 手机 B 不做本地修改，重新打开 App。
3. 手机 B 应自动下载服务器数据。
4. 手机 B 能看到手机 A 新增的物品。

### C. 冲突保护

1. 两台手机先同步到同一 revision。
2. 两边都先断开网络或不要同步，各自新增不同物品。
3. 手机 A 恢复网络并同步成功。
4. 手机 B 再恢复网络并同步。
5. 手机 B 应提示“本机和服务器都有新修改”，不得自动覆盖。

### D. 离线

1. 关闭网络。
2. 新增物品。
3. App 应正常保存本机数据。
4. 同步状态显示服务器不可连接。
5. 恢复网络并回到 App 后，应继续自动同步。
